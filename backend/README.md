# StayFinder — Hotel Backend

Node.js + Express + PostgreSQL API designed for the uploaded React/Vite StayFinder frontend.

## Features

- Hotel CRUD: create, list, details, update, delete
- Search across hotel title, city, and description
- Price filters and sorting (`price-asc`, `price-desc`, `rating-desc`, `title-asc`)
- PostgreSQL table/index initialization on server start
- Validation for title, description, price, latitude, longitude
- Image upload endpoint for JPG/PNG/WebP (max 5 MB)
- Static image hosting from `uploads/`
- Health check: `/api/health`

## 1. Requirements

Install Node.js 18+ and PostgreSQL 14+. Create a database named `stayfinder`.

```sql
CREATE DATABASE stayfinder;
```

## 2. Install and configure

```bash
cd hotel-backend
npm install
cp .env.example .env
```

Edit `.env` and set your PostgreSQL username/password in `DATABASE_URL`.

Example local connection:

```env
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/stayfinder
PORT=5000
CLIENT_ORIGIN=http://localhost:5173
```

## 3. Run the API

```bash
npm run dev
```

The `hotels` table is created automatically when the server starts. Visit `http://localhost:5000/api/health`; expected response:

```json
{"status":"ok","database":"connected"}
```

## 4. Connect your frontend

In the frontend root, create `.env`:

```env
VITE_API_BASE_URL=http://localhost:5000/api
VITE_USE_BACKEND=true
```

Restart Vite after changing `.env`:

```bash
npm run dev
```

Your existing `src/services/hotelService.js` already checks `VITE_USE_BACKEND` and uses `/api/hotels` endpoints. The list API returns `{ "data": [...], "total": 0 }`, which matches the current frontend service.

**Important image note:** the current frontend's form creates a temporary `blob:` preview URL. A blob URL cannot be stored and used by other users or after refresh. To persist uploaded images, send the selected file to `POST /api/uploads` as `FormData` with field name `image`, then save the returned `imageUrl` with the hotel. Example:

```js
const formData = new FormData();
formData.append('image', imageFile);
const response = await fetch('http://localhost:5000/api/uploads', {
  method: 'POST',
  body: formData,
});
const { imageUrl } = await response.json();
// Include imageUrl in the hotel create/update JSON body.
```

Do not manually set the `Content-Type` header for a `FormData` request; the browser supplies its multipart boundary.

## API reference

### List and search
`GET /api/hotels?search=ooty&minPrice=1000&maxPrice=10000&sortBy=price-asc`

Response:
```json
{ "data": [], "total": 0 }
```

Optional server pagination:
`GET /api/hotels?page=2&limit=6`

Supported sort values: `default`, `price-asc`, `price-desc`, `rating-desc`, `title-asc`.

### Get one
`GET /api/hotels/:id`

### Create
`POST /api/hotels` — JSON body:
```json
{
  "title": "Nilgiri Grand Retreat",
  "description": "A peaceful mountain hotel with comfortable rooms and scenic views.",
  "city": "Ooty, Tamil Nadu",
  "imageUrl": "https://example.com/hotel.jpg",
  "altText": "Hotel surrounded by green hills",
  "latitude": 11.4064,
  "longitude": 76.6932,
  "price": 8500,
  "rating": 4.8,
  "reviewsCount": 342,
  "originalPrice": 11000,
  "amenities": ["Free WiFi", "Free Breakfast"],
  "featured": true
}
```

### Update
`PUT /api/hotels/:id` — send the same fields as create.

### Delete
`DELETE /api/hotels/:id`

### Upload image
`POST /api/uploads` — multipart form field `image`; JPG, PNG, WebP up to 5 MB. Response:
```json
{ "imageUrl": "http://localhost:5000/uploads/your-file.webp" }
```

## Notes

- IDs are generated by PostgreSQL and returned as strings to fit React route params.
- The API validates data on the server even if the frontend already validates it.
- Uploaded files are stored locally for development. For production deployment, use object storage (e.g. S3-compatible storage) and a managed PostgreSQL service.
- This starter API has no authentication; add authentication and authorization before exposing hotel management endpoints publicly.
